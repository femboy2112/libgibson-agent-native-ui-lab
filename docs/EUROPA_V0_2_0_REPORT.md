# LibGibson v0.2.0 Europa-shot external consumer campaign

The three polished branches are integrated with ordinary merge commits. Issue status was checked on 2026-09-27 UTC.

## Experimental design

Three separately developed applications consume the released LibGibson v0.2.0 Rust API. Galileo stresses an experimental semantic UI plus subcell scientific graphics; Palimpsest stresses large, irregular repository data, native scrollback, and the lower `Node`/`Surface`/`Context` layer; Synesthesia stresses continuous graphics alongside an independent audio callback. The distinct domains expose different interfaces and failure modes. All were built in the same broader campaign, so the projects are **application holdouts**, not blind evidence from independent model or tool families.

The original lab campaign on `main` at `0fbb38f83c586784fc9e80bb27ee825dcdf3b433` tested manga, reactions, instruments, Foldroom, Cuebox, and Weavebench against frozen LibGibson commit `e5ede0a4ab8ff52caa567ee10d45824e42c1ebc6`. Its freeze receipt, 61-test result, and final research report are historical evidence. They remain intact and are not v0.2.0 experiments. Three Europa branches forked from that main. Local integration started from the same main, then ordinarily merged Galileo `46f83734e6e2a7cc204a17e1f1ed650a7d0758b6`, Palimpsest `51e2a78301a541e4b532e61739e6a7f673f068c9`, and Synesthesia `25bab4f632f567c133a8f1e3829cc5bf1d297263` in that order, preserving parentage at merges `b7d530f3bd54263c50176394baaea5c8bfc20f0e`, `e57c967510fb85d91813dc7367d1fdcf487a69d7` and `688dcba0e9ef8cd2f20d57affcb30b90e4360cf0`.

## Frozen dependency

Each application `Cargo.toml` in the local integrated tree declares `libgibson = { git = "https://github.com/femboy2112/libgibson", tag = "v0.2.0" }`. All three integrated `Cargo.lock` files resolve the released library commit `7a10e60bb55f58cec3364dad125bf1ae9127b0d2`. No project manifest has a local LibGibson path or patch override, vendored library, or unpublished branch dependency. Local `path = "src/..."` declarations on Cargo targets are ordinary source file locations, not dependency overrides. The lab root continues to use its older frozen LibGibson revision for the historical corpus. No LibGibson source modification belongs in this campaign.

LibGibson calls v0.2.0 **Engineering Alpha**, with Linux x86_64 the best tested platform. Its `gibson::ui`, Scene, Story, and software graphics APIs are experimental Rust interfaces; success in these consumers does not establish API stability or platform support.

## Projects

### Galileo — scale and semantic scientific graphics

`europa/project-galileo/` combines a deterministic **procedural** Jovian model, mission telemetry, surface and trajectory views, and illustrative radar/tomography. It is the **only** Europa consumer of `gibson::ui` (`UiRuntime`, keys, skins, semantic components, controlled input, and motion). It composes `RgbRaster` and `BrailleCanvas` graphics through custom `Surface` elements. Polished remote branch `46f83734e6e2a7cc204a17e1f1ed650a7d0758b6` added anchored apertures between adjacent scenes at spacious widths, atomic scene changes at compact widths and a modeled Earth signal light-time readout with a new regression. It does **not** implement a continuous spatial coordinate system or physically validated n-body/instrument model. Its suite reports 23 passing integration tests. A fresh-clone 3,600-frame, 120×40 headless profile of the final source tree `a5c664f` averaged 0.69 ms frame construction/render and 5,686 ANSI bytes/frame on an AMD EPYC host; neither number measures interactive refresh. Evidence: [Galileo experiment report](../europa/project-galileo/EXPERIMENT_REPORT.md).

### Palimpsest — irregular information and terminal history

`europa/project-palimpsest/` is a read-only Git archaeology workstation. It builds bounded commit indexes, braided history, file strata, diff, blame/provenance, search, repository health and finalized scrollback artifacts. It deliberately uses lower `Node`, `Surface`, `Context`, and `FocusRing` APIs; it **does not exercise `gibson::ui`**. Polished remote branch `51e2a78301a541e4b532e61739e6a7f673f068c9` records 89 passing tests, rendered-wire reconstruction, deterministic fixtures of 24, 152 and 2,890 commits, an interactive PTY scrollback probe and a 14-commit read-only local repository smoke. Polishing addressed initial tag/rail collisions, hunk navigation, search and health/provenance attribution; a real-repository health-view regression now reserves the actual metadata width so long subjects cannot run into path counts at 120, 80, or 42 columns. Its report now calls later commits on the same numbered line **positional context**, with a regression so append-only edits cannot be misattributed to blame origin. A published clean clone passed formatting, check, 89 tests, and strict Clippy. Evidence: [Palimpsest experiment report](../europa/project-palimpsest/EXPERIMENT_REPORT.md).

### Synesthesia — sustained audiovisual graphics

`europa/project-synesthesia/` is a four-track keyboard music workstation. Pattern and patch control a live audio callback and a separate deterministic visual simulation; `Node`/`Surface`/`BrailleCanvas`, headless Context, capabilities, and differential statistics are exercised. It **does not exercise `gibson::ui`**. Polished remote branch `25bab4f632f567c133a8f1e3829cc5bf1d297263` corrected numeric patch-entry semantics, transport changes, width-aware modal help and a denser FFT/stereo field driven by shared control state. A silent virtual-time profile ran 9,000 frames at 30 FPS spacing with mean 1.03 ms, ~1,680 exact changed cells and ~5,954 bytes/frame; a 15 FPS spacing run of 3,600 frames had similar mean. Both include a duplicate measurement pass under `--profile`, sleep for no real-time cadence, and opened no audio device. The polished suite reported 15 tests and two 5-second PTY runs receiving 88/88 application keys, one with 90 ms paused output. Earlier pre-polish audio probes observed nonzero PCM, but **post-polish hardware audio was not retested**. A published clean clone passed check and 15 tests. Evidence: [Synesthesia experiment report](../europa/project-synesthesia/EXPERIMENT_REPORT.md).

## Cross-project findings

### Rendering and deterministic inspection

All three found a public path for composing custom terminal graphics with text and chrome, without modifying LibGibson. Headless Context and explicit time/seed permitted reproducible visual probes; Palimpsest additionally rebuilt the **visible screen** from actual ANSI wire output to catch regressions that simple substring tests miss. The available public headless output is wire bytes, not a ready-made visible-frame snapshot (#48). Its test harness initially misparsed `CSI G`, creating a false renderer suspicion; the library diff was not shown broken. Galileo's initial report conflated discrete view swaps with continuous scale, now corrected to named scene reveals with explicit compact handoffs. Synesthesia tested an empty pattern as a negative control and pulse/offbeat patterns as distinct visible frequency/output outcomes; the visuals share controls with, but are not sample-identical to, live audio. Palimpsest ships deterministic rendered-wire captures; Galileo's headless cells and Synesthesia's fixed captures were inspected during individual polish. A merged-tree visual review was completed as a separate gate.

### Layout and responsive composition

Custom `Surface`s must be constructed with concrete cell dimensions before layout. Galileo and Synesthesia compute visualization dimensions outside layout; Palimpsest reported that intrinsic `Node::surface` sizing can push a sibling offscreen in a flex row (#43 and #48 E-05). These are related size-awareness pressures with distinct API manifestations. The semantic `Element` lacks the lower `Node` percentage sizing (#36). Palimpsest's lower `Node` composition owns breakpoint decisions (#42); experimental `gibson::ui` already offers `row().responsive(width)` for a width threshold, so "no responsive breakpoints" cannot be stated for the whole v0.2.0 API. Each project authored compact priorities: Galileo tested down to 60×20, Palimpsest to 42×15, and Synesthesia retains core track/route labels at 60×20 while a 44×14 fallback displays a resize message. This establishes those authored views and checks, not subjective legibility on every terminal.

### Focus and interaction

Galileo demonstrates a `gibson::ui` text-input hotkey routing defect (#35) and initial keyed-element motion trap (#37), addressed in that application by pre-routing Alt chords and suppressing unwanted fixed-capture entrance motion. Palimpsest's lower `FocusRing` lacks removal/reshaping; app-owned dynamic pane and filtered-list focus were checked by model, interaction and PTY resize tests (#40). Synesthesia owns modal/input routing, corrected narrow modal instructions and reported 88/88 key receipts in both short post-polish PTY probes, including one 90 ms output pause. These are different mechanisms and do not constitute three independent evaluations of semantic `UiRuntime` or closure of issue #15.

### Custom graphics, Surface, and capability fallback

Galileo combines `RgbRaster` and Braille overlays, Palimpsest paints dense Git topologies into Surfaces, and Synesthesia draws a continuously changing signal field. Galileo's manual Braille-on-RGB compositing and Palimpsest's manual clip guards are lower-layer ergonomics (#43 and #48 E-06), not demonstrated expressive impossibility. Each owns its domain-to-geometry mapping. Capability coverage differs: Galileo tests TrueColor, ANSI256/16 and authored Mono; Synesthesia tests Braille/halfblock/block/ASCII with the color ladder; Palimpsest tests ANSI256, ANSI16 and Mono, **not TrueColor**. The Galileo inspection font lacked Braille coverage, limiting what those screenshots show about fine glyph geometry. Other terminal/font behaviors remain untested.

### Performance and retained state

The polished reports show bounded probes, not cross-machine guarantees. Galileo **withdrew** its initial high-throughput and interactive-VSync claims; a fresh-clone 3,600-frame headless virtual-time profile at 120×40 on final source tree `a5c664f` averaged **0.69 ms** frame construction/render and 5,686 ANSI bytes/frame, with output drained each frame. Palimpsest's newer single-run 120×40 first frames were ~391 µs at 24 indexed commits, ~397 µs at 152, and ~346 µs at 2,890 (index load 36 ms), with an index limit (default 5,000) and lazy/cached statistics; these timings do not extrapolate to arbitrary repository shape. Synesthesia's polished 9,000-frame silent run averaged **1.03 ms**, ~1,680 exact changed cells and ~5,954 bytes/frame. Its richer signal field emits more changed cells/bytes than the original implementation on another host; the cross-host timings do **not** establish a causal speedup. Two short post-polish PTY silent runs delivered 88/88 application keys, but neither proves the #15 adversarial backend race fixed. Warm/end RSS and bounded spectral history are finite-session observations, not a leak proof. Context exposes affected dirty-cell footprint but not the renderer's exact semantic changed-cell scalar (#47). The three frame timings use different workloads and do not rank engines or platforms.

### Scrollback and diagnostics

Palimpsest's PTY probe confirms native insertion of a finalized artifact above a still-interactive live region. Its aligned preformatted text path can wrap columns or silently truncate wider content (#45), and an interactive Context under piped/non-TTY stdout can idle blank unless the consumer checks `session.is_tty` (#46). Issue #48 also records a separate rootless-render `Ok`/no-output trap. Synesthesia's successful bounded key probe did **not** reproduce the exact resize/input-readiness collision tracked by existing issue #15, which remains open.

## What appears strong in LibGibson v0.2.0

1. **Public composition across three quite different domains.** Existing `Node`/`Surface`/Braille or raster paths support custom visual grammar without private renderer access or source patches in the applications. This is observed for these projects and code paths only.
2. **Headless capture and controllable capability degradation.** Deterministic captures and fallback checks span several sizes and color/glyph modes. Palimpsest's multi-frame wire tests checked what a terminal actually presents, rather than source-level intent.
3. **Live-region/scrollback semantics under a real app.** Palimpsest inserted and retained a finalized artifact with a live UI continuing below. This is one consumer's bounded PTY evidence, not three independent scrollback probes.
4. **Differential/frame accounting on realistic loads.** All three report small local render costs in particular configurations; Synesthesia and Palimpsest actually measured frame/wire stats. Measurement instruments and individual workloads differ, so the raw figures are not a benchmark ranking.

## What appears weak

- **Semantic interaction surprises:** Galileo's #35 and #37 are specific v0.2.0 `gibson::ui` behavior discrepancies with directly inspectable code paths. They need focused regressions and remedies upstream, outside this consumer campaign.
- **A size-aware custom graphics seam:** pre-sized Surfaces force consumers to duplicate layout math and can conflict with flex allocation. Galileo, Synesthesia, and Palimpsest provide distinct application costs of the same family (#43/#48 E-05).
- **Large irregular data needs consumer policy:** bounded windows, focus restoration, visible-range math and responsive tiers occupy repeated application logic in Palimpsest (#38–#42). This is substantial ergonomics evidence from one lower-tier consumer, not proof that a particular core widget design is required.
- **Silent/noisy boundaries:** no-root render, non-TTY interactive silence, unsafe width semantics for aligned artifacts, and missing visible-screen snapshots frustrate debugging and reliable output (#45/#46/#48). Keep distinct mechanisms distinct.
- **Observability:** exact changed cells exist in the renderer but are not exposed through Context (#47). Profiler duplication is measurable consumer overhead; the baseline report did not isolate that overhead from its overall frame time.

## Candidate priorities for 0.2.x / 0.3.0

These are evidence-led candidates, **not** a committed release roadmap:

1. Reproduce and address the narrow behavioral defects #35 and #37; define Alt chord routing and stable key versus entrance-motion contracts.
2. Make interactive failure and finalized text semantics explicit: #46 non-TTY detection, #48 no-root diagnostics, and #45 safe preformatted artifacts. Favor a small contract with positive/negative tests over a broad framework.
3. Prototype an allocation-after-layout custom surface callback, including clipping and flexible sizing, against all three projects' real canvases (#43/#48). Test whether it actually eliminates duplicated geometry without an expensive universal two-pass build. A related transparent Braille overlay helper and clipped `Surface` view are narrower alternatives (#43/#48).
4. Use Palimpsest's seven bounded lists and filtering interactions to evaluate minimal visible-range/ensure-visible/focus-membership helpers (#38–#41), and explain lower `Node` and experimental `ui` responsive capabilities accurately (#42).
5. Expose the already computed exact semantic changed-cell scalar after a Context render (#47) without changing ABI-1 stats structs; tighten the untitled rule constructor (#44).
6. Continue existing #15 with an adversarial layer-specific resize/readiness/backpressure probe. Synesthesia's positive short session is insufficient to close it.

## Limits and next discriminating work

Three applications cannot prove universal expressivity, professional usability, accessible visualization, or a stable `gibson::ui` contract. Same-campaign tooling/model family and shared user/repo context can correlate design choices and blind spots. Palimpsest and Synesthesia use lower layers, so only Galileo directly tests semantic keyed reconciliation, skins and controls. The branch reports mix deterministic tests, a specific Linux PTY environment, and author judgments; their figures are not independent benchmarks. Claims about visual hero quality require inspected captures, not code size or reports alone.

Linux-specific PTY, capability and font coverage is finite; fine Braille detail was not represented by the Galileo screenshot host's font. Galileo's synthetic radar and prescribed orbital physics do not validate scientific fidelity or one integrated spatial camera. Palimpsest's ~2,890-commit maximum fixture is not a 100k-commit monorepo stress result, and its braid indexes HEAD ancestry while separately showing non-ancestral branch tips only in health metadata. Synesthesia's **pre-polish** nonzero PCM callbacks and connected stream do not prove current physical listening quality, sample-identical live/visual DSP, or long-run underrun freedom; its newer silent stress probes did not open an audio device. Short warm/end RSS equality does not prove leak freedom. v0.2.0 remains **Engineering Alpha**.

The next discriminating work is a truly independent model/developer cohort, broader terminal platform matrix, long-session retention and adversarial issue #15 input race probe, plus tests of whether a deferred-size canvas actually removes work in all three consumers without new layout or rendering regressions. These are future research questions, not release claims.
